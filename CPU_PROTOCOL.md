# CPU execution amendment · November 26, 2026

The author elected to run this study without linking a payment method. Modal requires one for its GPU functions. The funded CPU path uses the same three frozen checkpoints, factual and contextual maps, prompts, independent worlds, and acceptance thresholds as the [original protocol](plato/protocol.md). The amendment was written after the two-variant benchmark smoke test and before either model pair was evaluated on held-out private worlds.

## What changes

- Model forwards run on Modal CPUs in FP32. Each transmitted packet is still serialized as BF16, hashed and decoded before injection. Report actual CPU allocation, elapsed inference time, hardware-specific throughput and provider gross cost. GPU-seconds are zero.
- The controls that require a sender to name its private category and a receiver to apply the rulebook with full evidence can run ahead of calibration. An initial four-way audit uses four physical cores and 32 GiB per worker on the 64 validation worlds. Its result describes prompt and task readiness.
- Use eight physical cores and 32 GiB per scientific worker. Benchmark complete worlds and a representative factual screening batch on this allocation. Run independent shards only while their combined worst-case cost fits the relevant stage allowance. Merge factual-screen generations in the same deterministic order before selection.
- If the registered controls fail on validation, keep all 250 private test worlds sealed. Report factual intervention results and the validation diagnosis, including raw answers. Any subsequent prompt experiment is identified separately, with its data split, scorer and outcome.

The working budget is $170 in credits. Stop paid work before the displayed grant expiration. All published costs identify the measurement period and source. The working outputs and checkpoints live on a named Modal Volume, and the public replays require no running model.
